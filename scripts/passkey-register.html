Register a passkey

Manual step. Produces two public values to paste back — nothing secret.

1 · Create

Forces alg: -7 (ES256 / secp256r1) — the only curve the on-chain verifier supports — and requires user verification, because the contract rejects an assertion whose User Verified flag is unset.

2 · Paste these back

Both are public. The private key stayed in the authenticator; this page never saw it and makes no network requests.

3 · Check it signs (recommended)

Produces one assertion and reads the authenticator flags. Worth doing now: if User Verified comes back unset, the contract would refuse every transaction from this passkey, and it is better to find that here.

Notes

  • A passkey is bound to the origin it was created on, so this one belongs to . It still works on chain because the verifier deliberately skips origin and rpIdHash validation — see docs/ARCHITECTURE-v2.md §4. Re-register per origin once that gap is closed.
  • Testnet only.
